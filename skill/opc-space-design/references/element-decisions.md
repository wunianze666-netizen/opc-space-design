# 设施取舍

先沿使用者和维护人员的路线检查完整性，再做布置。办公室看进入、工作、会议、补给、废弃物、设备与清运。住宅看入户、睡眠、起居、厨卫、家务及储物。零售看浏览、试用、结算、取货、退换、补货及清洁。墙地顶、照明和装饰服务这些活动。

1. **确认用途。** 明确谁用、频率、峰值人数和用户在意的体验。打印、单人舱、直播、充电等专用设施应由实际活动触发。颜色和风格用于在可行方案之间取舍。
2. **先看现有设施。** 有可达、可用、容量合适的点位时优先复用。小空间的寄放和储物可用同一处浅柜，垃圾和分类回收可在同一区分开投放。需要验证开放时间、清运、操作和错峰条件。
3. **判断现场和尺寸。** 记录有无电、采光、给排水、可固定基层、净高和维护。未知条件列待核，明确受限时试另一种做法。例如保留可移动灯具，按不接管比较桶装饮水。按实际外廓和操作空间检查家具、开口、门扇和通行。
4. **决定采用或省略。** 需要且可放时补进模型。空间冲突时先比较换位、缩小、合并或复用，保留已确认的关键用途。功能可由现有布置覆盖，或新设施没有实际用途时，写一条理由即可。已采用的物件在平面与三维中用同一编号。

`suggest` 的 `provided` 用现有设施覆盖一项已确认用途，例如 `{"饮水":"入口旁的公共饮水点，营业时段可用"}`。结果的 `decisions` 给出选用、条件待核、排除或复用及原因。无法映射的用户用语继续随对话细化。

`office-services` 的 `shared` 用配套标识记录已确认可共用设施，例如 `{"printing":"本层电梯厅旁共用打印室，员工可进入"}`。同一个配套选择共用或明确暂缓。结果同时给出当前布置和各项新增、合并、共用、待核、省略或保留理由。通过 `overview --brief` 复核实际布置后，在办公配套下打开「查看设施取舍」。

做交叉验证时，可用同一个场地只改一条条件，也可更换面积、用途和图纸。保留至少一个实际布局通过的例子和一个有理由拒绝的例子。需要判断设备能否落位时，以同坐标布局校核为准，方案初筛数量用于设计讨论。
