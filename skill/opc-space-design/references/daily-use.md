# 日常配套与装饰设计

先走一遍用户的一天。谁进门，手上带什么，在哪放包、看信息、接水、休息、讨论和归还东西。对每个使用场景选出需要的配套，然后在平面上检查相邻关系、取用和维护空间。可更换的内容交给使用者，长期固定的构件服务动线和空间气氛。

## 从使用场景选元素

| 场景 | 适合考虑的搭配 | 放进去前要看 |
| --- | --- | --- |
| 入口与访客 | 可换壁报、访客导向、雨伞和随身物收纳、低位接水盘、识别转向的落地盆栽 | 门扇范围、等候站位、海报能否停下看、挂衣后突出多少 |
| 茶水与补给 | 饮水机、杯具与接水盘、分类回收、窄边台、清洁备品 | 取水和回收能否在同一支路完成，电源、供水方式、换桶或清运路线 |
| 安静工作 | 共用文具、理线、临时包位、阅读角、储物和吸声面 | 是否影响拉椅、工作照度和安静区；低频设备可集中到边侧 |
| 共享与展示 | 项目进展墙、可换展架、可移动白板、低柜与可挪座椅 | 展品更换、停留视线、双侧操作和储存是否冲突 |
| 绿化与软装 | 转角盆栽、可维护绿植槽、窗边植物、局部织物或地面分区 | 光照、维护路线、接水托盘、叶片最终展开范围及不挡窗、开口和通道 |

小场地优先做合并配套，例如饮水和杯具共用一个台面，壁报用墙面。多人或频繁接待的场地可以把停留点和主路线分开。用户希望低维护时减少盆栽数量并集中养护。根据现场条件选择方案，保留可替换的装饰。

## 主动检查办公配套

整区设计从峰值在场人数和工区出发。每次先看饮水与杯具、分类回收、日常垃圾、入口寄放、清洁用品、个人和公共收纳。再按现场用途决定打印扫描、短时充电、导视与壁报、访客接待、用餐、会议、安静通话、共创、展示和绿化。写清哪里取用、谁负责补给，哪些可以合用。

```powershell
python scripts/run.py office-services <项目.json> --brief <办公配套.json>
```

```json
{
  "peak_people": 32,
  "uses": ["接待", "会议", "打印", "充电", "绿化"],
  "conditions": {"power": true, "water": false, "drainage": false, "daylight": null, "maintenance": null},
  "avoid": ["不接水"]
}
```

人数未提供时沿用项目工位数。有多个相隔较远的工区时，比较两侧分设饮水和回收点的便利性。参考数量用于方案，结合楼层使用方式、现有物业设施和补给频次决定最终数量。点位数量够但挤在同一侧时，总览提示核对另一组的取用路线。

人数和面积用来估算已需要的设施规模。独立打印和充电由使用活动、已有设备或用户需求触发。已确认可共用的设施填入 `shared`，狭小空间可比较合用位置。详见 [设施取舍](element-decisions.md)。

现场条件用 `true`、`false` 或 `null` 表示已具备、明确缺少或未知，未填也按未知。给排水未知或不能改管时可比较桶装饮水，缺电时可考虑手动取水。具体设备和换桶、排水或清洁仍应核实。无纸化可用 `defer: {"printing": "无纸化办公"}`。按实际底图保留的设备可用 `retained: [{"ref": "S002", "kind": "water_station"}]` 指定，先核对其固定物编号和实际可用性。

## 写进方案和效果图

`requirements.furniture` 支持饮水与杯具站 `water_station`、分类回收柜 `recycling_station`、入口收纳 `entry_organizer`、落地盆栽 `potted_plant`、日常垃圾桶 `waste_bin`、打印扫描站 `print_station`、保洁备品柜 `cleaning_cabinet`、分格储物柜 `locker_bank` 和共享充电站 `charging_station`。可在同一层按实际位置放多件。尺寸和取用带用现场与设备实际条件覆盖默认值。核对挂衣、杯具、开盖、抽桶、柜门和植物展开后的空间。

壁报使用 `requirements.interior.elements` 中的 `notice_board`，可用 `cork` 软木色。线段挂在已确认的实体墙上，并避开开口。三维里的纸张表示排版与信息区，交付画面可配真实活动内容。没有相应点位时先保留为方案候选。饮水和绿植的位置由现场供电、供水与光照条件确定。

将同一份配套说明作为 `overview --brief` 文件的 `office_services` 字段。总览会按本版实际编号核对数量、已布置但待核的设施，以及未覆盖的用途。先用[整区总览](whole-space-overview.md)说明所有区域和逐件位置，再补便于看清小物的局部。绘制局部时沿用同一版模型的家具尺寸和相对位置。采购是用户要求时的后续工作。

[木廊会客配套示例](example-daily-use.json)与[已校核位置](example-daily-layout.json)可用 `generate --layouts references/example-daily-layout.json --brief` 复现。场景包括入口壁报、随身物收纳、转角盆栽和同一侧的饮水、回收。根据想表达的使用场景调整人视机位。
