# 整区设计与逐件查看

根据使用者、人数、日常动作和底图确定功能。先识别要保留的墙柱、门窗、固定设备和已指定的物件，再确定哪些能移动或增设。和用户确认范围变化，所有拟布置元素进入方案数据。

- 办公优先理解日常办公、访客接待、会议或交流、茶水补给和物品收纳。有并发需求时比较独立空间和共用空间。是否需要封闭茶水间、接待台、电话位或样品柜根据实际情况决定。
- 住宅从进门放物、起居、用餐、睡眠、衣物收纳及厨卫出发。按常住人数、做饭频率、换衣动作和物品量选择家具。原图只确认厨卫范围时把设备明细留待核对。
- 零售按进入、浏览、试用、结算和补货设计。展架、停留区和员工通路结合货物与来访人数选择。

先出标注区域名称的整区平面和整体剖切图。人视适合看局部材质和使用场景。整区中的每件家具、装修构件、固定物、门窗和洞口应能查到。颜色区块表示分区，实体落位及尺寸以所选方案为准。

```powershell
python scripts/run.py overview <方案包目录> --option A --brief <整区说明.json> --out <新目录>
```

总览页面可离线打开。点平面、三维或物件列表看位置、已有尺寸和所属区域。未知设备、标高或点位留作待确认。剖切只用于查看，底图仍记录完整边界和开口。图中的家具尺寸采用该件本体的宽、深、高，门窗尺寸取已知标注。

整区说明为可选 JSON，字段为 `summary`、`zones`、`needs`，也可记录 `layout_sha256` 以核对版本。分区写 `name/polygon/note`，多边形在可用楼板内并互不重叠。功能写 `name/refs/note`，用物件编号指出该功能怎么实现。没有对应位置时保留空列表并说明待确认项。

`selections` 可写 `name/refs/spec/note`。所引用的编号均来自本版方案，用户点选物件就能同时查看规格和定位。平面定位值相对底图左、下外接边界，家具取本体外接范围左下点，线段取起点。家具转向按原布局角度标注。

`patterns` 可以把参考纹样绑定到本版已校核的墙面或地面 D 编号。页面按实体范围显示试铺、重复尺度和余边，点击纹样联动该物件。文件要求与试铺口径见 [饰面纹样与试铺](material-patterns.md)。

`office_services` 接收 [办公配套说明](daily-use.md#主动检查办公配套)，核对本版饮水、垃圾与回收、保洁、储物等设施的已布置数量、对应分区与现场待核事项。点选任一对应物件查看位置与尺寸。

大空间可用 `detail_views` 指定最多六个局部，按所选物件的相对位置生成一张《配套局部》。每项用 `name`、`refs` 和可选的 `angle`、`note`。例如 `{"name":"西区打印和废纸","refs":["F075","F076"],"angle":15,"note":"设备正面向办公侧。"}`。选择彼此相邻的已校核家具或装修构件，视角从操作面看。整区图用于看分布，局部图用于看物件形态和相对位置。

加 `--quality studio` 可另行导出带真实纹样的同坐标 Blender 整区剖切和人视 PNG。页面中的可点选几何和饰面记录用于定位，贴图渲染用 PNG 或 Blender 工程查看。

编号按所选方案的记录顺序生成。F 为独立家具或组合内的部件，D 为墙地顶设计，S 为保留结构或设备范围，O 为门窗，V 为洞口。餐桌和每把椅子都有自己的编号。改版后重新导出并核对整区说明引用。

复现办公样例可用 [底图与需求](example-daily-use.json)、[布局](example-daily-layout.json)和[整区说明](example-daily-overview.json)。住宅样例可用 [底图与需求](example-compact-home.json)、[布局](example-compact-home-layout.json)和[整区说明](example-compact-home-overview.json)。先用 `generate --layouts` 生成方案包，再用 `overview` 读所选版本。
