# 按需求选择风格

先根据使用者提出几个有实际区别的方向。用一句话说明各方案服务的活动、材质和光线。保留用户确认的底图、人数、功能和沿用家具。风格方向要改变至少一项用户在意的空间体验，例如更容易展示样品、更清楚地收纳，或更舒服地停留。只想换色时保留原布局。

## 先从活动找物件

按进入、使用、收纳与维护检查空间。办公从访客、安静工作、协作、饮水与回收出发。住宅看进门随手放、充电、阅读、衣物和家务。零售看第一视线、驻足、试用、结算和补货。在这个基础上选墙面、地面、顶面、灯光和小设施。每套方案挑一处值得做出特色的场景，讲清使用者走到那里会做什么。

用 [设计元素库](design-library.json) 过滤场地和已明确的限制。它涵盖线光、吸声、充电、饮水、家务防潮、退换与库存等功能、物件和饰面。采用新物件时，先写清用途、参考规格、所占空间和维护动作。用 [设施取舍](element-decisions.md) 处理沿用设施和不适合的候选。选出的做法要回到实际平面校核开门、操作和通行。

```powershell
python scripts/run.py suggest <需求摘要.json>
```

```json
{
  "space": "office",
  "style": "科技感",
  "area_m2": 120,
  "needs": ["接待", "展示", "照明", "安静"],
  "avoid": ["不接水"],
  "keep": ["原六人会议桌"],
  "conditions": {"power": true, "wall_mount": true, "ceiling_mount": null, "daylight": false}
}
```

省略的现场条件和 `null` 都表示待核。明确为 `false` 时跳过依赖该条件的做法。面积只是初筛依据。输出的 `groups` 是概念物件，`finish_directions` 是墙地纹样和起始模块，`pending` 是待核事项。保留用户自定义的风格原话，根据已知用途先给可用物件，再结合用户描述补充配色、纹样和氛围。没有把握时只问一个会改变方案的偏好，或提供两个可选方向。

## 将风格变成能看见的做法

- **科技感。** 办公项目可用清楚的展示背景、理线柜、线性任务灯和雾灰地面。若需要识别度，把确认过的公司字样和原创图形用作一处视觉焦点，灯光与收边围绕它设计。住宅可集中充电与影音设备，保留家庭收纳和休息区。设备电源、散热和使用面按实际选型。
- **简约。** 先减少视觉上的散碎感，集中收纳并保留连续通行。可用暖灰或米白墙面、浅色木纹地面、低突出量的日常置物件。保留已确认功能和物件，兼顾清洁与收口。
- **自然绿化。** 用木色、低饱和绿和可维护绿植区分停留与工作。办公优先看共享区与维护路线，住宅优先看窗边光照和床边活动空间。把植物含托盘和叶片的外廓放入平面。

用户提出其它风格时先确定色材和使用重点。可用 `requirements.interior.materials` 声明实际颜色及做法名，例如：

```json
{"mist_floor":{"name":"雾灰石纹地面","color":"#71868c"}}
```

墙地顶元素的 `material` 引用标识。家具可用 `color_hex` 指定本体方案色。可用定尺设备和现有模板表达明确外廓的物件。用 [饰面试铺](material-patterns.md) 预览图案密度、朝向和裁边。品牌样板、复杂曲面和安装节点按项目深化。

同一底图比选时，对每套分别建模和校核墙、地、顶、固定物、家具与操作区。保持原有通行、门窗和原结构。整区说明的 `selections` 写 `name/refs/spec/note`，将建议选的地面、墙面或物件规格连到已建模编号。以一张整区总览和可点选的尺寸、位置、朝向交付。不同方案里的物件编号分别对应各自版本。

可用科技住宅[项目输入](example-style-tech-home.json)、[布局坐标](example-style-tech-layout.json)与[选型说明](example-style-tech-selection.json)复现自定义颜色、选型和位置。先用 `generate --layouts` 出方案，再用 `overview --brief` 查看所选方案。
